# Output Routing — 输出后续分流规则

> 本文件定义每次产出后，如何建议用户下一步行动。
> SKILL.md 主文件通过引用本文件保持简洁。

---

## 分流总览

每次产出后，根据内容类型建议一步行动，让学习不中断：

| 输出内容 | 建议下一步 | 说明 | 触发方式 |
|---------|-----------|------|----------|
| 每日学习笔记 | "需要我把核心知识点生成卡片保存吗？" | 触发知识卡片提取（Mode 1 延伸） | 自动弹出一次 |
| 知识卡片 | "想用这几个知识点做一次模拟面试自测吗？" | 触发 Mode 4 面试 | 自动弹出一次 |
| 进度报告 | "看到你在 [domain] 上已有积累，需要我针对弱项推荐学习路径吗？" | 触发补弱建议 | 自动弹出一次 |
| 代码详解 | "要不要自己不看代码复述一遍逻辑？我可以帮你检查" | 费曼学习法 | 自动弹出一次 |
| 连续 3 天同领域 | "这个领域已经连续 3 天了，要换一个拓展一下吗？" | 避免领域疲劳 | 自动检测 |
| 长时间未复习 | "上一次复习 [topic] 是 [N] 天前，需要温习一下吗？" | 间隔复习提醒 | 自动检测 |

---

## 分流触发条件详细定义

### 条件 1：连续同领域检测

```
扫描 learning-notes/calendar/ 最近 7 天记录
  ↓
同一 domain 出现 ≥ 3 次
  ↓
触发分流建议："这个领域已经连续 3 天了，要换一个拓展一下吗？"
```

### 条件 2：长时间未复习检测

```
扫描 learning-notes/cards/ 所有卡片的 mastery 字段
  ↓
上次复习日期距今天数 > 7 天（mastered）
                          > 3 天（understood）
                          > 1 天（exposed）
  ↓
触发分流建议："[topic] 已经 [N] 天没复习了，需要温习一下吗？"
```

### 条件 3：弱项识别

```
读取 learning-notes/progress.md
  ↓
找出 mastery ratio 最低（< 30%）的 domain
  ↓
触发分流建议："[domain] 掌握度偏低（XX%），建议优先补强"
```

---

## 分流建议输出格式

```
> 💡 下一步建议
> [具体建议内容]
> [是 / 否] （等待用户确认，不自动执行）
```

**重要约束**：
- 分流建议只输出一次，用户忽略（不回复"是"或"否"）则不重复
- 不支持的分流路径直接跳过，不输出错误信息
- 用户说"别提醒了" → 本次会话内不再触发分流建议

## 与网页端（Web Hub）的集成

当 Skill 在网页端环境中运行时，分流建议可以改为：

```
网页端额外动作：
1. 在界面上高亮显示建议入口（非弹窗，不打断）
2. 点击后直接跳转到对应功能页
3. 用户的点击/忽略行为被记录，用于优化后续建议时机
```

## 分流日志（可选）

如果用户开启"学习行为追踪"，每次分流建议的结果记录在：

```markdown
# learning-notes/analytics/routing-log.md

| YYYY-MM-DD | 输出类型 | 建议内容 | 用户响应 | 后续行动 |
|-------------|---------|---------|---------|---------|
| 2026-06-20 | 每日笔记 | 生成知识卡片？ | 是 | 创建了 3 张卡片 |
| 2026-06-21 | 进度报告 | 补强前端？ | 否 | 未记录 |
```

此日志仅供网页端做学习行为分析使用，Skill 本身不主动生成。
